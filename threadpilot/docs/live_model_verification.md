## 4. 异常与验证边界

- 批量调用触发 HTTP 429。复现脚本提供轮间间隔和 SDK 有界重试；工作流接口向客户端返回 429，调用方应退避。SQL Agent 的失败按接口契约返回 502。
- 连接失败的诊断批次及受日志采集空值错误影响的诊断批次不计入通过覆盖。有效结果仅使用第 2 节列出的两个批次，排除记录不作为成功证据。
- 外部发送网关的真实送达及生产部署验收不在已完成范围。Docker 本地启动的补充验证见第 6 节。部署时须验证业务连接、独立只读权限、迁移、导入和发送回执。
- 测试使用冻结业务日期和有限输入，不能推断其他日期、未见问题或任意负载下的准确率与可用性。

## 5. 证据归档与复现

可随仓库交付的摘要为 [reports/live_model_verification.json](reports/live_model_verification.json)。完整原始报告位于私有 `backend/runtime/<批次 ID>/report.json`，该目录不提交 Git；完整审计交接须通过受控附件提供原始文件，并核对摘要中的 SHA-256。摘要用于复核统计，不替代包含完整请求和回答的原始审计附件。

复现前安装开发依赖，建立专用 `threadpilot_test` 库并导入三表；`LIVE_DATABASE_URL` 指向该测试库，`LIVE_AI_DATABASE_URL` 使用该库独立 SELECT-only 账号。模型连接由应用环境配置提供。脚本会产生真实 API 用量，并临时修改测试订单数量后恢复；禁止使用生产数据库。

```powershell
cd backend
uv sync --locked --group dev
# 设置 LIVE_DATABASE_URL、LIVE_AI_DATABASE_URL 和模型环境配置后执行
uv run python -m scripts.verify_live_llm
```

`LIVE_SCENARIOS` 可用逗号选择完整场景；`LIVE_CALL_INTERVAL_SECONDS` 控制轮间间隔，默认 3 秒。报告输出到 `backend/runtime/live-*/report.json`。如需重新评估限流场景，应运行完整场景以建立确认上下文，并按批次分别报告结果。
